# CRM / изнутри

Открытый проект Павла Егорова о технической базе CRM-маркетолога.
Пока опубликованы основа сайта и образец оформления; учебные статьи ещё не написаны.

- Сайт: https://pavelegorov-ru.github.io/crm-course/
- Черновая версия для вычитки: https://pavelegorov-ru.github.io/crm-course/review/
- Репозиторий: https://github.com/PavelEgorov-ru/crm-course
- Основа: Astro и Starlight. Оформление ориентируется на страницы документации Kanri.

## Локальная работа

Нужна поддерживаемая версия Node.js (для проекта используется Node 24) и npm.

```sh
npm ci
npm run dev -- --background
```

Адрес разработки: `http://localhost:4321/crm-course/`.
Остановить фоновый сервер: `npm run astro -- dev stop`.

```sh
npm run build
npm run preview
```

`build` собирает сайт и поисковый индекс в `dist/`.
`preview` позволяет проверить именно собранный сайт, включая поиск.

## Материалы

- [Редактор черновой версии](https://app.pagescms.org/PavelEgorov-ru/crm-course/codex%2Fdrafts/collection/articles) — Pages CMS, личный GitHub `PavelEgorov-ru`, ветка `codex/drafts`. Используйте эту ссылку: вход через корень редактора может открыть основную ветку репозитория.
- В разделе «Статьи» можно создавать материалы, оформлять текст и вставлять загруженные картинки. Раздел «О проекте» позволяет редактировать существующую страницу. Код и Markdown для этого не нужны.
- Меню Pages CMS повторяет существующую навигацию сайта: «Начало» → «Главная», «О проекте»; «Статьи»; «Демонстрация» → «Образец страницы». Страница 404 находится отдельно в «Служебных страницах» и не входит в обычное меню сайта.
- Для новой статьи откройте «Статьи» и нажмите **Add an entry**. Для редактирования нажмите название существующей статьи или **Edit**. Коллекция показывает папки деревом; выбранная папка определяет вложенность статьи в разделе. Поле «Порядок в меню» задаёт порядок страниц одной папки; сортировка списка в CMS сама по себе порядок сайта не меняет.
- Сохранение в черновой ветке запускает обновление сайта для вычитки. После успешного завершения GitHub Actions можно отправить специалисту ссылку на нужную страницу чернового сайта. Основной сайт сохраняет последнюю отдельно одобренную версию.
- Настройка редактора хранится в `.pages.yml`. Для активации нужен однократный вход владельца и установка GitHub App Pages CMS.

Статьи хранятся в обычном формате сайта и в своих будущих разделах. Отдельная папка черновиков не требуется: рабочую версию отделяет ветка. Пометка `draft: true` в Markdown дополнительно исключает страницу из обычной сборки, но в черновой версии она видна. Снятие этой пометки само по себе не публикует статью на основном сайте.

Черновой сайт доступен по ссылке без авторизации, имеет заметную пометку и метатег `noindex, nofollow`. Это открытая версия для вычитки, а не закрытое хранилище. Изображения и поиск используют собственные файлы черновой сборки.

- `src/content/docs/` — страницы Markdown и MDX.
- `src/content/docs/articles/` — статьи из визуального редактора; автоматически попадают в меню «Статьи».
- `public/images/` — загруженные картинки; публичные ссылки начинаются с `/crm-course/images/`.
- `src/components/` — интерактивные демонстрации.
- `src/styles/custom.css` — палитра и небольшие изменения оформления.
- `astro.config.mjs` — навигация, язык и адрес сайта.

Обычная статья — файл `.md` в `src/content/docs/articles/` с заголовком `title` и необязательным описанием `description` в начале. Редактор создаёт эти файлы сам. Положение в меню задаётся полем «Порядок» (`sidebar.order`); без него используется стандартная сортировка Starlight.

Главная и демостраница используют MDX-компоненты. В Pages CMS они доступны как отдельные страницы: заголовок и описание — обычные поля, содержимое — редактор MDX с сохранением импортов и компонентов. Они не входят в коллекцию статей с визуальным редактором. Соблюдайте префикс `/crm-course/` у абсолютных внутренних ссылок; относительные ссылки тоже поддерживаются.

## Публикация

`.github/workflows/deploy.yml` запускается при изменениях `codex/drafts` и вручную. Он собирает две версии: основной сайт из закреплённого коммита и черновой сайт из рабочей ветки. Затем обе сборки размещаются одним комплектом: основной сайт в корне, черновой — под `/review/`.

Публичная версия определяется переменной репозитория GitHub Actions `PUBLIC_SITE_COMMIT`, содержащей полный SHA одобренного коммита. При её отсутствии сборка останавливается. Последний `main` не используется как запасной вариант. Поэтому обычное сохранение, отправка ветки и даже изменения `main` не выбирают новую публичную версию.

**Обновлять основной сайт можно только по отдельной команде Павла.** После такой команды исполнитель:

1. Переносит именно одобренные изменения в `main`, проверяя, что прочие черновики не попали в выбранную версию.
2. Проверяет обычную сборку выбранного коммита, страницы, картинки, ссылки и исключение материалов с `draft: true`.
3. Записывает полный SHA этого коммита в `PUBLIC_SITE_COMMIT` и вручную запускает `deploy.yml` из `main`.
4. Дожидается успешной сборки и развёртывания, затем проверяет публичный адрес. При ошибке сообщает фактическое состояние; успешная отправка коммита не считается успешной публикацией.

Пока отдельной команды нет, переменная публичной версии не меняется. В Pages CMS нет автоматического действия, которое продвигает черновики на основной сайт.

Для локальной проверки черновой версии:

```sh
npm run build:review
npm run preview:review
```

Для фоновой разработки: `npm run dev:review -- --background`. Адрес — `http://localhost:4321/crm-course/review/`; обычная сборка остаётся в `dist/`, черновая — в `dist-review/`.

Все действия с GitHub для этого проекта выполняются от `PavelEgorov-ru`. Авторизация другого аккаунта, используемого для остальных проектов на компьютере, не должна переключаться глобально.
